> 作者：C 角色　|　更新：2026-08-26
> 对应方案指标：项目方案 §8.4「用户测试（5-10 名大学生）」
> 测试脚本：`scripts/user_testing.py`（研发者测试 · 10 画像）+ `scripts/real_user_testing.py`（3 名真实同学）（C 新增，未改动 B 的任何代码）

---

## 1. 测试目标与两层设计

验证「反馈记忆」在真实会话链路（规划 → 理解检验 → 恢复）上确实产生个性化价值，并量化 5 项指标。

**关键方法论决定**：主观指标不能由设计者自评（那只是在验证系统符合设计意图，不是验证它对学生有价值）。因此拆成两层：

| 层 | 脚本 | 执行者 | 产出 | 用途 |
| --- | --- | --- | --- | --- |
| 层一 · 研发者测试 | `user_testing.py` | 研发者按 10 画像做功能覆盖 | used 计数、跨课程隔离、软删、时长差等**客观证据** + 功能覆盖设计 | 验证四步会话的**功能正确性** |
| 层二 · 真实用户 | `real_user_testing.py` | 3 名真实同学 | 5 项**主观指标** + 开放反馈原话 | 验证对真实学生的**外部效度** |

5 项主观指标**只采信层二（3 名真实同学）**的数据；层一不产出主观结论，只证明功能能跑、闭环能闭合、记忆能命中/能隔离。

| 指标 | 定义 | 数据来源 |
| --- | --- | --- |
| 计划修改次数 | 用户对 Agent 规划结果的修改次数 | 层二 plan 步 |
| 个性化结果接受率 | 个性化产出（`used>0`）中「接受」的比例 | 层二 plan/check 步 |
| 恢复后继续学习率 | 收到恢复建议后「继续学习」的比例 | 层二 recover 步 |
| 理解程度（1-5） | 用户对「Agent 为什么这样调整」的理解 | 层二 收尾 |
| 有记忆偏好评分（1-5） | 有记忆 vs 无记忆版本，用户偏好 | 层二 compare 步 |

## 2. 层一：研发者测试（10 画像功能覆盖演练）

**执行方式**：研发者按 10 个画像做功能覆盖，每个画像专攻一种测试维度——覆盖三类记忆消费点（`task_preference` / `explanation_preference` / `recovery_experience`）+ 四个边界（冷启动、跨课程隔离、冲突偏好软删、混合全链路）。

**目的**：功能走查，不产主观结论。验证 plan 的「修改 → `/feedback` → 重排」闭环、check 的「问题 → 回答 → 评估层级 + 反馈」两步、recover 的「接受 → 存为新记忆」闭环都能跑通，并产出 used 计数（个性化是否发生）、跨课程隔离（`used=0`）、软删（旧偏好不串）等客观证据。

**预热方式**：画像 1、10 走 `POST /feedback` 主链路（顺带演示核心卖点）；其余画像用 `POST /memories` 直写 confirmed 记忆（快、确定）。

## 4. 会话流程（层一，真实对话走查）

每个画像按需执行以下真实交互（不再只看一眼就评分）：

1. **预热**：按画像种记忆（feedback 或 memories；画像 9 额外软删旧偏好）。
2. **plan（含修改闭环）**：`POST /agent/plan` 打印任务/说明/used 数 → 画像决定要不要改；要改就提一句反馈（`POST /feedback` 生成记忆）→ `POST /agent/plan` 重排看是否自动用上 → 录入修改次数、是否接受。
3. **check（两步）**：`POST /agent/check`（不传 answer）出问题 → 画像**真的回答** → 再 `POST /agent/check`（带 answer）拿评估层级 + 针对回答的反馈 → 录入个性化讲解是否接受。
4. **recover（含接受闭环）**：`POST /agent/recover` 打印动作/理由/used → 画像决定是否继续；继续则带 `user_acceptance=true` 再调一次，把动作存成新恢复记忆 → 录入是否继续学习。
5. **compare**（画像 1、10）：`POST /evaluation/compare` 打印有/无记忆对照 → 录入偏好评分（1-5）。
6. **理解程度**（有记忆被 used 的画像）：录入 1-5。

每步都会打印 `used` 记忆数，作为「个性化确实发生」的客观校验——只有 `used>0` 的步骤才计入「个性化接受率」分母，冷启动/隔离（used=0）为对照组、不计入。

## 5. 层二：3 名真实同学（主观指标来源）

### 5.1 执行方式

C 当主持人，同学**不碰键盘**。找 3 名同校同学（大连理工），各约 10 分钟，按同学自己的话题和真实反应走一遍会话；C 把同学的口头回答与评分录入 `real_user_testing.py`。

### 5.2 主持流程（每名同学）

1. **开场**（1 分钟，向同学说明）：这是一个学习助手，会记住你的学习习惯。你先告诉它今天想学什么，再说一个你的学习习惯，它会帮你规划。过程中我问你几个问题，你按真实想法答，没有对错。
2. **定任务**：问「今天想学哪门课、什么知识点、大概多少分钟」→ 录入。
3. **说习惯**：问「你学习上有什么习惯？一句话说清（比如每次学多久、喜欢先看定义还是先看例子、累了怎么办）」→ 录入（`POST /feedback`，生成记忆）。
4. **plan（含修改闭环）**：给同学看计划 → 问「你会改吗？」→ 改了就说改成什么 → 重排看是否自动用上 → 问「接受吗」。
5. **check（两步）**：出问题 → 同学口头回答 → 看评估层级 + 针对性反馈 → 问「这个讲解符合你的习惯吗」。
6. **recover（含接受闭环）**：设一个卡点场景（太难/累/分心/没时间，同学自己说卡在哪）→ 看建议 → 问「你会继续学吗」。
7. **compare**：给同学看有/无记忆两个版本 → 问「有记忆的更贴合你吗？1-5」。
8. **收尾**：问「理解系统为什么这样调整吗？1-5」+「整个过程哪里最有帮助 / 最别扭？」（原话记录）。

### 5.3 运行命令

```bash
# 每名同学跑一次（后端已启动）
python scripts/real_user_testing.py --base-url http://127.0.0.1:8000 --student r-01
python scripts/real_user_testing.py --base-url http://127.0.0.1:8000 --student r-02
python scripts/real_user_testing.py --base-url http://127.0.0.1:8000 --student r-03
```

结果追加写入 `outputs/real_user_results.csv`；每次跑完自动读取全表，打印截至当前的 5 项主观指标汇总。

## 6. 如何运行（层一）

后端已启动时（`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`）：

```bash
# 只看画像清单
python scripts/user_testing.py --list

# 跑全部 10 个画像（交互式录入评分）
python scripts/user_testing.py --base-url http://127.0.0.1:8000

# 只跑部分（如画像 1、10，用于快速验证或补录）
python scripts/user_testing.py --base-url http://127.0.0.1:8000 --only 1,10
```

结果追加写入 `outputs/user_testing_results.csv`，跑完打印 5 项指标汇总。

> 注意：api.openai-next.com 中转站延迟波动大（单次 LLM 调用 5s~128s）。升级真实对话后，plan 每改一次 = 1 feedback + 1 重排（约 3 次 LLM 调用）、check 两步 = 2 次、recover 接受闭环 = 2 次；画像 10（3 feedback + 全链路）可能 15+ 次 LLM 调用，单画像可能要几分钟，请耐心。
