# StudyFlow Memory 项目演示视频文稿

建议时长：7—8 分钟  
演示主线：同一名学生学习 BFS，依次完整展示弹性任务流、专注倒计时、思绪星云、苏格拉底伴学、复习计划、反馈记忆和个人中心，最后用后续相似任务证明记忆被自动复用。

## 录制前准备

- 启动后端和前端，确认页面顶部显示“Agent 在线”。
- 使用固定演示用户，例如 `demo-user`，避免不同用户之间的记忆串扰。
- 演示开始前删除该用户旧的“任务偏好”和“解释偏好”，但保留一组预先验证过的课程材料。
- 打开一个备用标签页：`/metrics` 用于展示真实运行指标。
- 先完整彩排一次并记下本次真实的 Token、检索耗时和模型耗时。视频中只念实际显示的数据，不使用预估数字。
- 如果模型响应较慢，保留加载状态并适当剪辑等待过程，不剪掉请求前后的关键页面状态。

## 0:00—0:30 开场：真实问题与方案

### 画面

展示 StudyFlow 首页和产品标志，随后快速扫过“弹性任务流、理解检验、思绪星云、个人中心”四个模块。

### 旁白

> 大家好，我们的项目是 StudyFlow Memory，一个能够从用户反馈中持续改进的轻量学习 Agent。
>
> 我们选择的真实场景是大学生的日常学习。传统学习助手每次都从零开始：它不知道用户喜欢多长的任务、不知道用户遇到困难时需要怎样的帮助，也不会把一次学习中的经验带到下一次任务。
>
> StudyFlow 将“计划、执行、反馈、记忆、再计划”连成一个闭环。接下来，我们用一次 BFS 学习任务展示：用户的反馈如何被沉淀，并在后续相似任务中被自动检索和真正使用。

屏幕字幕：`Plan → Tool Use → Result → Feedback → Memory → Better Plan`

## 0:30—1:30 弹性任务流：输入、导入与智能规划

### 画面操作

1. 进入“弹性任务流”。
2. 先点击“添加”，展示用户可以补充课程、知识点和截止时间；再关闭弹窗。
3. 点击任务导入入口，展示可以粘贴文本或导入 TXT/CSV 任务材料；保留一条导入结果进入时间线。
4. 在快速调整中输入：
   - 课程：`数据结构与算法`
   - 知识点：`BFS`
   - 可用时间：`25`
   - 截止时间：选择当天稍晚时间
5. 点击“生成今日计划”。
6. 展示“现在最值得做”卡片、推荐理由、截止时间、任务状态和今日任务时间线。
7. 简短展示任务的添加、删除和顺延能力，但不要删除后续需要演示的 BFS 任务。

### 旁白

> 用户既可以手动输入任务，也可以导入已有的学习清单。Agent 结合课程、知识点、可用时间和截止时间，自动读取学习状态、检索相关记忆，并调用预置工具拆分和安排微任务。
>
> 生成后，“现在最值得做”卡片会自动排除已经完成的任务，并从未完成任务中推荐当前优先项。用户也可以添加、删除或顺延任务，计划会保留在统一任务流中。
>
> 这里不是让大模型直接修改数据库。模型只能从受控工具中选择，所有工具参数都经过结构校验，计划结果再由服务端保存。

### 技术字幕

`自动检索相关记忆 → get_learning_state → split_learning_task → adjust_learning_plan → 生成任务`

## 1:30—2:10 专注倒计时：不中断的弹性执行

### 画面操作

1. 点击“开始学习”，进入倒计时。
2. 让倒计时运行数秒，记住当前剩余时间。
3. 点击“时间不够”，输入 `10`，展示系统在当前剩余时间上追加 10 分钟，而不是把总时长重置为 10 分钟。
4. 继续运行数秒，然后点击“释放杂念”。

### 旁白

> 任务开始后进入专注倒计时。用户感觉时间不足时，可以直接追加时间；新增时长会叠加在当时的剩余时间上，不会抹掉已经完成的进度。
>
> 如果学习中出现困难、疲惫或分心，用户可以随时进入思绪星云。离开倒计时页面时，系统会保存当前任务和剩余秒数，返回后从原位置继续。

## 2:10—3:15 思绪星云：把自然语言反馈转化为恢复行动

### 画面操作

1. 完整展示星空背景、“仅自己可见”和当前任务信息。
2. 输入：`这个知识点学不会，好难。`
3. 点击发射，完整保留星星沿轨迹飞入星云的动画。
4. 展示 Agent 识别“难度过高”，并调用恢复工具生成低压力建议。
5. 点击接受建议，展示当前任务降低起步难度，并在进入星云时的剩余时间基础上增加 10 分钟。
6. 返回弹性任务流，展示“反馈记忆已影响本次调整”的提示，再点击“继续学习”，证明倒计时没有从头开始。
7. 再次进入思绪星云，输入：`记得取快递。`
8. 发射后返回倒计时，展示这类无关杂念只被释放，不增加任务时长，也不改变学习目标。
9. 用快切补充输入 `有点累，注意力不集中。` 和 `时间不够，来不及了。`，分别展示疲惫恢复动作与时间调整建议。

### 旁白

> 这里是思绪星云，它不是一个普通留言框，而是学习 Agent 的情境反馈入口。用户可以把压力、困难、疲惫或无关杂念用自然语言发射到星空，并且默认仅自己可见。
>
> 当用户输入“学不会，好难”，系统识别为难度阻塞，调用生成恢复行动工具，给出一个低压力、可立即执行的建议。用户接受后，弹性任务流会降低起步难度，并在进入星云时的剩余时间上追加十分钟。
>
> 现在返回任务，倒计时从之前保存的位置继续，而不是重新开始。接着我们输入“记得取快递”，系统把它识别为与任务无关的分心内容，只帮助用户释放杂念，不错误增加学习时长。对于“有点累”和“时间不够”，系统则分别提供减压恢复与时间调整建议。由此，Agent 会根据反馈语义选择不同动作，而不是依赖固定按钮。

屏幕字幕：`太难 / 时间不足 / 疲惫 / 无关杂念 → 不同恢复行动`

## 3:15—4:30 苏格拉底伴学：根据回答选择引导策略

### 画面操作

1. 进入“理解检验”，选择 BFS 任务。
2. 点击“选择文本”，展示支持输入文本及接入 TXT、Markdown、PDF、Word、图片材料的入口。
3. 点击“开始伴学”，进入独立对话页面。
3. 回答第一问：`我不会。`
4. 展示“示例、定义、类比、图示”四种轻量提示选择。
5. 选择“图示提示”，展示流程图式提示，而不是直接公布答案。
6. 再回答一个不完整答案，让 Agent 指出缺失点并继续追问。
7. 用户输入：`直接告诉我答案吧。`，展示 Agent 能在明确请求时给出完整讲解。
8. 继续回答最终问题，展示掌握状态和复习建议。
9. 点击“完成”或“退出伴学”，展示会话总结弹窗。

### 建议回答

- 不完整回答：`BFS 就是把相邻节点一个个访问。`
- 完整回答：`BFS 使用先进先出的队列。从起点开始，节点入队时就标记访问；每次取出队首，把它所有未访问邻居标记并入队，因此节点按距离起点的层数被访问。在无权图中，第一次到达某节点时经过的边数最少。`

### 旁白

> StudyFlow 不是一次性公布答案，而是通过“复述、关联、迁移”逐层判断理解程度。
>
> 当用户说“我不会”时，系统先让用户选择解释偏好，只给轻量提示。选择图示后，Agent 以真实的步骤节点呈现 BFS 的队列变化，再继续追问。根据后续回答，它可以选择提示、纠错、完整讲解或进入下一层问题。
>
> 如果用户明确要求完整答案，Agent 才切换到完整讲解；之后仍会继续提问，验证用户是否真正理解，而不是把“看过答案”等同于掌握。
>
> 每一次有效回答都会形成理解证据。完成或退出时，系统根据整段对话生成中文掌握总结，并建议复习日期。

## 4:30—5:05 掌握总结与复习计划

### 画面操作

1. 在会话总结中展示中文掌握层级、已掌握内容和仍需补充的维度。
2. 查看系统建议的复习日期，并手动选择一个未来日期。
3. 点击“加入计划并退出”。
4. 回到弹性任务流，展示原有今日任务仍然存在；新复习任务被安排在所选日期，不会错误出现在今天。
5. 如果时间允许，再演示“暂不加入，直接退出”和“继续伴学”。

### 旁白

> Agent 不用单次答题的对错简单定义掌握，而是综合整段对话，形成可解释的掌握总结，并指出仍然欠缺的机制、关联或迁移能力。
>
> 系统会建议复习日期，但最终由用户确认。加入计划时采用追加而不是覆盖，原有任务保持不变；未来日期的复习任务也不会混入今日时间线。

## 5:05—5:55 把反馈沉淀为可控记忆

### 画面操作

1. 进入“个人中心—我的反馈记忆”。
2. 提交第一条反馈：`我希望每个学习任务控制在 15 分钟以内。`
3. 选择“任务偏好”，勾选“这是我的明确偏好”，保存。
4. 提交第二条反馈：`讲算法时先给我看图示，再讲定义。`
5. 选择“解释偏好”，勾选明确偏好，保存。
6. 再提交一条不勾选明确类型的自然语言反馈，展示模型自动分类后进入待确认状态。
7. 展示记忆卡片的类型、课程/知识点范围和确认状态，并演示确认、修改、拒绝或删除。

### 旁白

> 反馈不会直接拼接进永久上下文。系统先把自然语言分类成任务偏好、解释偏好、恢复经验或复习安排，并带有用户、课程、知识点和任务类型等作用域。
>
> 对明确反馈，用户可以直接确认；不够明确的内容由模型分类后进入待确认状态。只有已确认记忆能够影响 Agent，待确认记忆只能作为候选。用户始终可以确认、修改、拒绝、归档或删除，因此记忆是透明、可控、可追溯的。

屏幕字幕：`retrieved ≠ used；只有 confirmed memory 可以进入 used_memory_ids`

## 5:55—6:45 后续相似任务：自动检索并使用记忆

### 画面操作

1. 返回弹性任务流。
2. 输入一个相似任务：
   - 课程：`数据结构与算法`
   - 知识点：`DFS`
   - 可用时间：`25`
3. 生成计划。
4. 展示新任务时长被任务偏好约束在 15 分钟以内，以及界面中的“反馈记忆已影响本次计划”提示。
5. 再进入 BFS 理解检验，展示同一知识点下系统优先采用图示方式。
6. 展示本轮返回的检索、使用和候选记忆引用。

### 旁白

> 现在我们创建同一课程下的相似任务 DFS。Agent 会自动检索相关记忆，而不需要用户重复输入偏好。
>
> 可以看到，原本 25 分钟的可用时间没有被机械地全部占满，任务时长遵循了同一课程下“单个任务不超过 15 分钟”的偏好。随后我们再次进入 BFS 理解检验，系统也优先采用用户刚刚确认的图示解释方式。这里分别展示了课程级任务偏好与知识点级解释偏好的作用域。
>
> 更重要的是，系统区分了“检索到”和“实际使用”。只有真正改变本轮结果的记忆才进入 used memory，避免看似命中、实际没有产生作用的伪个性化。

> 注意：如果现场模型生成的任务并未体现 15 分钟限制，不要口头声称已生效；应先检查该记忆是否为 confirmed、作用域是否匹配，并重新演示。

## 6:45—7:15 个人中心与运行指标

### 画面操作

1. 进入“个人中心”，展示学习概况、掌握分布和反馈记忆数量。
2. 展示“完成不等于掌握”：任务完成状态与对话产生的理解证据分开记录。
3. 打开 `GET /metrics`，简要展示本次真实运行数据：
   - input/output/memory tokens
   - retrieval latency P50/P95
   - model latency P50/P95
   - retrieved/used/candidate 数量
   - 成功、失败、重试和格式修复次数

### 旁白

> 个人中心把任务完成情况、知识掌握证据和反馈记忆集中呈现。系统明确区分“做完任务”和“真正掌握”，掌握状态必须来自理解检验中的回答证据。
>
> 为了控制轻量 Agent 的成本和速度，系统只检索少量相关记忆，只有实际注入的已确认记忆计入 memory tokens。每次运行都记录输入、输出和记忆 Token，并分别记录检索耗时与模型耗时的 P50、P95。
>
> 当前画面中的真实数据是：检索耗时 P50 为【现场数据】毫秒，P95 为【现场数据】毫秒；模型耗时 P50 为【现场数据】毫秒，P95 为【现场数据】毫秒；本轮记忆上下文消耗【现场数据】Token。这样我们可以同时评估记忆效果、成本和响应速度。

## 7:15—7:45 架构总结与收尾

### 画面

显示一张简洁闭环图，或在页面间快速回放：任务输入 → 计划 → 学习 → 反馈 → 记忆中心 → 相似任务。

### 旁白

> StudyFlow 的核心不是多保存几轮对话，而是把反馈变成结构化、可确认、可检索、可审计的长期记忆。
>
> 整个 Agent 闭环是：接收任务，检索相关记忆，规划并调用受控工具，生成结果；再从用户修改、回答和反馈中提取经验，经过确认后用于下一次相似任务。
>
> 在真实学习场景中，这让 Agent 逐渐理解每位用户的节奏、解释偏好、困难恢复方式和知识掌握状态，在保持轻量成本的同时，越用越贴合用户。以上就是 StudyFlow Memory，谢谢观看。

## 建议的关键字幕

- 不是保存完整聊天记录，而是沉淀结构化反馈记忆
- 自动检索相关记忆，只有已确认且实际生效的记忆才参与结果
- 受控 Tool Calling：读取状态、拆分任务、调整计划、生成问题、恢复学习
- 思绪星云理解困难、疲惫、时间不足和无关杂念，并选择不同恢复动作
- 真实记录 Token、检索耗时、模型耗时与失败轨迹
- 用户可确认、修改、拒绝和删除记忆

## 录制风险与备用方案

- 模型服务异常：录制前访问 `/health` 并完成一次真实请求；不要使用旧的过期 Key。
- 返回格式异常：先在演示前清理异常运行，保留一次成功链路；若现场失败，可展示错误码和失败轨迹，但不能称为成功结果。
- 记忆未生效：确认用户 ID、课程、任务类型、知识点范围一致，且状态为 `confirmed`。
- 指标数字为零：先完成计划、理解检验和恢复各一次，再刷新 `/metrics`。
- 演示时间不足：优先保留“任务规划—思绪星云—苏格拉底伴学—反馈记忆—后续任务自动复用”五段；添加/删除任务和个人中心可以快切展示。
